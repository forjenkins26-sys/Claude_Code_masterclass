Pipeline architecture

From a Jira story to a triaged test run, without a human in the middle

Eight stages carry one ticket all the way through: an agent reads it, drafts the plan and cases against everything the team has tested before, writes the automation, runs it, and hands back a root-cause analysis of whatever broke.

JQL→ Test plan→ Test cases→ Flow files→ Execution→ RCA
1

Intake

Fetch the stories a JQL query returns

A LangChain or CrewAI agent runs the query and collects every story, feature, or ticket waiting to be covered.

inJQL query outstory list
2

Intake

Take one story at a time

The agent works the list in sequence. Everything downstream is scoped to a single ticket — VWO-109, say — so artifacts never blur across stories.

instory list outVWO-109
3

Generation

Draft a test plan against prior art

The agent queries the RAG pipeline, which already holds the team's earlier test plans and testing documentation, and writes a plan for this story that follows the house shape rather than inventing one.

inVWO-109 inRAG: past plans outtest plan
4

Generation

Generate the cases

A second pass over the RAG store — this time for prior test cases, reusable patterns, and domain knowledge — produces the cases that cover the plan.

Decide the oracle. Retrieved cases say what was tested before; the story's acceptance criteria say what must be true now. When they disagree, the criteria win — otherwise a bug encoded in an old case propagates as expected behaviour.

intest plan inRAG: past cases outtest cases
5

Automation

Turn cases into flow files

Another agent reads the generated cases and writes .md automation flows, using the Playwright framework as its reference for structure and conventions.

intest cases refPlaywright framework out.md flow files
6

Execution

Run them through Browser Bash

A CLI runner executes the flow files unattended. It can drive a cheaper model — DeepSeek or similar — since this stage follows written steps rather than authoring them.

in.md flow files outlive run
7

Execution

Emit the run as data

The run lands as result.json — pass and fail status, errors, logs, and the rest of the execution detail.

outresult.json
8

Analysis

Analyse, triage, publish

The results go back to a LangChain agent, which checks for flakiness, performs root cause analysis, triages the failures through an RCA bot, and pushes the outcome to the dashboard.

inresult.json outflakiness outRCA outdashboard

What the pipeline delivers

01Reads Jira stories straight from a JQL query
02Writes test plans grounded in earlier ones
03Generates cases from historical coverage
04Converts cases into Playwright flow files
05Executes the flows through Browser Bash
06Produces machine-readable run results
07Analyses failures, flakiness, and root cause
08Publishes everything to a reporting dashboard
